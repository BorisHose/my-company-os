Offen für weitere Systeme Vorschlag

Company OS spricht die Systeme dahinter nur über eine Anschluss-Schicht an. Jeder Anschluss beschreibt, welche Grundaufgaben das System übernimmt: Kontakt, Aufgabe, Termin, Dokument, E-Mail, Projekt, Katalog. Prozesse und Phasen nennen nur diese Grundaufgaben, nicht Bodo oder sellify direkt. Ein neues System per MCP braucht dann einen neuen Anschluss, aber keine neuen Prozesse.

Je Kundeninstanz ist festgelegt, welches System angeschlossen ist. Hat ein System eine Grundaufgabe nicht, zeigt Company OS das beim Einrichten als Lücke.

Vertretung Boris

  • Je Abteilung eine Vertretung neben der Leitung.
  • Die Leitung trägt eine Abwesenheit mit Zeitraum ein. In dieser Zeit gehen Freigaben, Rückfragen und Eskalationen an die Vertretung. Vorschlag
  • Reagiert die Leitung nicht innerhalb einer Frist, geht eine Eskalation zusätzlich an die Vertretung. Die Frist ist je Abteilung einstellbar. Vorschlag
  • Im Verlauf steht, wer entschieden hat: Leitung oder Vertretung.

Menschen in der Abteilung Boris

  • Mitarbeitende werden je Abteilung aufgenommen, mit eigenem Avatar wie die Leitung.
  • Das Team einer Phase besteht aus Menschen und Agenten. Jede Aufgabe hat entweder einen Menschen oder einen Agenten als Bearbeiter. Vorschlag
  • Aufgaben für Menschen landen als Aufgabe im angeschlossenen System, z. B. als Bodo-Aufgabe beim Benutzer. Dort arbeitet der Mensch wie gewohnt. Vorschlag
  • Ein Mensch kann wie ein Agent in mehreren Abteilungen mitarbeiten: Heimat plus „unterstützt auch“. Vorschlag

Wann Leitung oder Vertretung informiert wird Vorschlag

  • Freigabe nötig: Aktion mit Außenwirkung, z. B. Daten nach Bodo schreiben, E-Mail an Kunden
  • Rückfrage: Agent kommt ohne Entscheidung nicht weiter
  • Eskalation: Fehler, Frist überschritten, Ergebnis unter der Prüfschwelle
  • Tagesbild: optional eine Zusammenfassung pro Abteilung, ohne Push

Warum ein Mensch je Abteilung Vorschlag

Aus der Recherche: Eingriffe von Menschen sichern die Qualität bei sachlichen Problemen, und frühes Eingreifen ist entscheidend (Feldversuch Alibaba). Praktiker empfehlen, Zuständigkeiten zwischen Mensch und Agent ausdrücklich aufzuteilen. Leitung, Vertretung und Mitarbeitende machen das sichtbar.

Technische Frage dahinter Annahme

Die heutige Anwendung ist eine private Seite in deinem Claude-Konto. Für Kunden braucht es eine eigene Anwendung mit Anmeldung, Mandantentrennung und Anbindung je Kunde. Drei Wege:

  • Vorführung: je Kunde eine Kopie der Seite. Schnell, aber nur für Demos tragfähig.
  • Eigenes Produkt: Webanwendung mit Claude über die Schnittstelle. Tragfähig, aber Entwicklungsaufwand.
  • Teil von Bodo: später als Modul. Für sellify-Kunden dann getrennt zu lösen.

Anregungen

  • Rückweg Betrieb → Vertrieb: Erweiterungen und Zusatzmodule als Auslöser, damit die Kette ein Kreislauf wird.
  • Phasen-Ergebnis als Abnahme: Jede Phase endet mit einem Ergebnis, das die Abteilungsleitung abnimmt. Das ersetzt viele Einzelfreigaben.
  • Demosystem als Startpunkt: Das Demosystem aus dem Vertrieb wird zur Ausgangsbasis für die Einrichtung. Der Skill zur Ersteinrichtung kann laut Beschreibung aus einem anderen Bodo-System übernehmen. Bodo
  • Vorführung als Produkt: Interessenten sehen in einer Musterinstanz, wie ihr eigener Verein in Company OS aussähe. Das beantwortet „Was kann KI für uns tun?“ konkret.
